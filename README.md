# OpenAPI generated server

## Overview
This server was generated by the [OpenAPI Generator](https://openapi-generator.tech) project. By using the
[OpenAPI-Spec](https://openapis.org) from a remote server, you can easily generate a server stub.  This
is an example of building a OpenAPI-enabled Flask server.

This example uses the [Connexion](https://github.com/zalando/connexion) library on top of Flask.

## Requirements
Python 3.5.2+

The package version is derived from Git tags via ``setuptools-scm``.

intended release commit.

## Installing code for development

First, clone this repository using:

```bash
git clone https://github.com/TNO/nexussim-server.git
```
then:
```bash
git submodule init && git submodule update
```

[Optional step, but highly recommended] Create a virtual environment.  In the repo root, type:
```bash
python -m venv venv && source venv/bin/activate
cd cDynAA && make wheel && pip install pydynaa*.whl && cd ..
cd nexussim && pip install .  && cd ..
pip install -r requirements.txt
pytest
```

## Usage
To run the server, please execute the following from the root directory:

```
pip3 install -r requirements.txt
python3 -m nexussim-server
```

and open your browser to here:

```
http://localhost:8080/dynaa/ui/
```

Your OpenAPI definition lives here:

```
http://localhost:8080/dynaa/openapi.json
```

To launch the integration tests, use tox:
```
pip install tox
tox
```

## Influx configuration
If using influx with nexussim-server, you can change the config via either influx.ini (in nexussim) or environment variables, e.g. INFLUXDB_V2_URL, INFLUXDB_V2_ORG, INFLUXDB_V2_TOKEN, INFLUXDB_V2_BUCKET. See [influxdb-client docs](https://influxdb-client.readthedocs.io/en/stable/api.html#influxdb_client.InfluxDBClient.from_env_properties).

## Running with Docker

To run the server on a Docker container, please execute the following from the root directory:

```bash
# building the image
docker build -t nexussim-server .

# starting up a container
docker run -p 8080:8080 nexussim-server
```

From this moment on, you can use `curl` to send requests. Example:
```bash
 curl -X POST -H "content-type:application/yaml" --data-binary "@example-control-segments.yaml"  -H "X-API-KEY: aaa" localhost:8080/dynaa/simulation
```
or
```bash
 curl -X POST -H "content-type:application/yaml" --data-binary "@example-uc-traffic.yaml"  -H "X-API-KEY: aaa" localhost:8080/dynaa/simulation
```

A remark here is that the tag `--data-binary` is necessary. Otherwise, the newline characters in the text file are ignored and the conversion on the server side goes wrong.

# Regenerating the server code
This is generated code.  To regenerate the code (e.g. after an update of the api specs) follow these steps.

## Preparation
Code generation requires the [open-api-generator-cli](https://openapi-generator.tech/docs/installation) application.  Use the python version with the embedded jdk. That is the simplest.

## Generation
In this root directory, use the command 
```bash
openapi-generator-cli generate -c nexussim-server-generation-config.yaml -i mirto-dynaa-v1-openapi.yaml
```

## Excluded from generation
in `.openapi-generator-ignore` a number of files are marked for exclusion. These files are not regenerated and overwritten with the above command.
Excluded file include this readme, and the Dockerfile. In terms of code most notably:
- `nexussim_server/test/test_simulation_controller.py` as generated tests test the wrong for status code (200 instead of 404)
- `nexussim_server/controllers/simulation_controller.py` and `nexussim_server/models/concurrent_segments_inner.py` the generated code contained circular imports (due to type checking) these have been fixed, but regenerating these files would reintroduce these errors.
   Changes compared to generated code are:
   - commented out imports of `Choice`, `Concurent` and `Repeat`
   - to help with type hints `ConcurrentSegmentsInner` and `RepeatSegmentsInner` are written in quotes inside list type hints (e.g. `def segments(self) -> List['RepeatSegmentsInner']:`)

*Explanation:*  this command generates the server code for the `mirto-dynaa-v1-openapi.yaml` specification.  The configuration of the code generation is in the file `nexussim-server-generation-config.yaml`
